deepfoundry/atlas-lm

複数のLLMを1つの入口にまとめて、乗り換えを怖くなくする

All-in-one LLM serving stack with routing, caching and evaluation built in.

github.com/deepfoundry/atlas-lm
Apache-2.0 · 商用OK Python ★ 9,880（今日 +4,120） 3日前に更新

どういうものか

複数の LLM を、ひとつの窓口の裏にまとめる道具です。アプリからは1か所を呼ぶだけで、どのモデルに渡すかは atlas-lm が決めます。OpenAI と同じ形式で話すので、既存のクライアントは接続先を変えるだけで繋がります。

中に3つの機能が入っています。リクエストごとにモデルを選ぶルーティング、同じ問い合わせを2度投げないキャッシュ、そして過去のリクエストを記録しておいて別のモデルに流し直せる評価です。この3つを別々のツールで揃えると設定が散らかるので、まとめてあることに意味があります。

どんなときに使うか

モデルを乗り換える前に、壊れないか確かめたいとき

1週間ぶんの本番リクエストを記録しておいて、切り替え前に新しいモデルへ流し直せます。「変えてみたら一部の返答が崩れた」を、本番に出す前に見つけられます。

コストと速度で、モデルを振り分けたいとき

「短い問い合わせは安いモデル、長文は高いモデル」といった振り分けを、アプリ側のコードを触らずに設定ファイルだけで変えられます。

使い方 編集部で動作を確認しました

1. インストールする
# Docker は要りません
pip install atlas-lm
2. 設定ファイルを書く
# atlas.yaml
backends:
  - name: fast
    model: gpt-4o-mini
    max_latency_ms: 800
  - name: deep
    model: claude-sonnet-4
    max_cost_per_1k: 0.01

上が速さ優先、下が品質優先の設定です。名前は自由に付けられます。

3. 起動して、アプリから呼び出す
atlas serve --config atlas.yaml

# 既存のクライアントは向き先を変えるだけ
client = OpenAI(base_url="http://localhost:8080/v1")

ここまでを macOS / Python 3.12 で確認しています。コード例は当サイトで書いたもので、README の転載ではありません。バージョンによって手順が変わることがあります。
