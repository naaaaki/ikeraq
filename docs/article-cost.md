# 記事1本にかかる消費量の実測

Claude Code の `/cost` を、記事を書く前と後に打って差を取ったもの。

## ★ ドルの数字は請求額ではない

Naoki は定額プラン（サブスク）を使っている。`/cost` が出す金額は
**「API を従量課金で使っていたら、いくらになるか」という換算値**であって、
実際に請求されるものではない。追加のお金はかからない。

**本当の制約は、`/cost` の下に出る使用量のバー。**

```
Current session   ███▌      7% used     ← 数時間でリセット
Current week      █████▌   11% used     ← 週ごとにリセット
```

金額は「枠をどれだけ食ったか」の目安として読むこと。

## ★ わかったこと

消費の大半は「記事を書くこと」ではなく **「会話の長さ」** で決まる。
記事を書くときは `/clear` するか新しいセッションを開く。それだけで5分の1以下になる。

### なぜキャッシュ読みが8割を占めるのか

Claude Code は毎回、それまでの会話全体を読んでから応答する。
会話が長いほど1回の応答が高くなる。**記事の内容とは関係なく積み上がる。**

この日は4時間ぶん（サイト実装・レビュー対応・GitHub 設定・収集の実行）が
積まれた状態だったため、その読み直しだけで $1.85 かかった。

## 見積もりの目安

| やり方 | 1本あたりのセッション枠 | 換算額（請求されない） |
|---|---|---|
| **新しいセッションで記事だけ書く** | **1%未満** | $0.3〜0.5 |
| 長い会話の続きで書く | 約1% | $2〜3 |

※ 上段は実測ではなく、下段の内訳から推定した値。次に新しいセッションで書いたとき、
　 実測に置き換えること。

**枠から見れば、週3本はまったく問題にならない量。** 1本で週の枠の1%も使っていない。
それでも会話を短く保つ意味はある。長い会話は、記事と関係なく枠を食うため。

### 費用を左右するもの（効く順）

1. **会話の長さ** ← 圧倒的にこれ。記事ごとに `/clear` するか新セッションを開く
2. **図（SVG）を作るか** — 出力が1〜2万トークン増える。$0.25〜0.5 の上乗せ
3. **直しの往復回数** — 1往復ごとに会話が伸びるので、2重に効く
4. **README の長さ** — 意外と効かない。2,000字でも12万字でも、入力は安い（$5/100万）

D-008「図は無理に入れない」と D-006「使い方は動かせたときだけ」は、
中身のための決まりだったが、費用の面でも効いている。

## 測り方

1. 記事を書く前に `/cost` を打つ
2. 記事を書く
3. もう一度 `/cost` を打つ
4. 差を上の表に追記する

★ トークン数をフックで自動記録することはできない（Claude Code が公開していない）。
　 OpenTelemetry を使えば取れるが、設定が重いので手動で足りる。
