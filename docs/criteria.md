# 判定基準

> `/about/criteria` に載せる原稿。Phase 1 でこのままページ化する。
>
> **この文書は `scripts/lib/thresholds.ts` と対になっている。**
> 閾値を変えたら、必ずこちらも直すこと。数字がずれた時点で、このページは価値を失う。

---

Wakuru に載っている警告は、すべて機械が自動でつけています。人が1件ずつ見て判断しているわけではありません。

そのため、**どういう条件で警告がつくのかを、隠さず全部公開します。** 基準が分からない警告は、読む側にとって判断材料になりません。

## 使っているデータ

判定に使うのは、次の2つだけです。

| データ | 取得元 |
|---|---|
| リポジトリの公開情報（スター数・fork 数・ライセンス・最終コミット日など） | GitHub の公式 API |
| 日々のスター数の推移 | Wakuru が毎日記録しているもの |

**AI による文章生成は使っていません。** 要約も翻訳も作っていないので、事実の取り違えは起こりません。掲載しているのは、取得した数値と、下記の計算式による判定結果だけです。

---

## 2つの軸を分けて見せています

Wakuru は、性質の違う2つのことを別々に表示します。混ぜると、どちらも読み取れなくなるからです。

| 軸 | 何を見ているか | 表示 |
|---|---|---|
| **実運用に耐えるか** | ライセンス・メンテ状況。業務で使えるか | 0〜100 の点数 |
| **数字が信用できるか** | スターの伸び方が自然か | なし / 低 / 中 / 高 |

「AGPL だから自社サービスには組み込みにくい」と「スター数が怪しい」は、まったく別の話です。ひとつの点数に潰してしまうと、どちらの理由で低いのか分からなくなります。

---

## 実運用に耐えるか（0〜100点）

100点から引き算します。

| 警告 | 条件 | 減点 |
|---|---|---|
| アーカイブ済み | 作者がアーカイブしている | −50 |
| 利用条件不明 | ライセンスが設定されていない | −40 |
| メンテ停止の疑い | 最終コミットから **180日**以上 | −30 |
| 自社サービス組込み注意 | GPL / AGPL などのコピーレフト系 | −15 |
| ドキュメントが少なめ | README が **500字**未満（README が無い場合を含む） | −10 |

下限は0点です。

### 補足

- **ライセンス未設定は、点数以上に重い意味があります。** 法的には全権利が留保された状態で、原則として利用できません。「まだ決めていないだけ」という場合も多いのですが、こちらからは区別がつきません
- **「ドキュメントが少なめ」は弱い警告です。** 単機能のライブラリでは、README が短いのが正常です
- README をまだ取得できていないリポジトリは、この判定の対象外です。「README が無い」と「まだ確認できていない」は区別しています
- ライセンスの区分は、GitHub API が返す SPDX ID から機械的に分類しています。GitHub が特定できなかったものは「不明」とし、商用可否を推測することはしません

## 数字が信用できるか（なし / 低 / 中 / 高）

### なぜこの判定をしているか

ある研究では、2019年7月から2024年12月までの間に **約600万個の偽スター**が検出されました。ピーク時には、50スター以上のリポジトリの **16.7%** が偽スターキャンペーンに関与していたと報告されています。

そして、その最大の受益分野が **AI / LLM 関連**です。いま最もトレンドに入りやすい分野が、最もスター数を信用しにくい分野になっています。

### 4つのシグナル

次の4つを見て、該当した数で段階を決めます。

| シグナル | 条件 |
|---|---|
| **スター速度の異常** | 直近の1日の増加が、過去7日平均の **10倍**を超える（増加が **50** 未満のときは判定しない。それまで増加がほぼ止まっていた場合は、**50以上の増加**があった時点で該当とします） |
| **低活動** | スターが **1,000**以上あるのに、fork がスターの **2%** 未満で、かつ 貢献者 **2人**以下 または Issue **2件**以下 |
| **新規性** | 作成から **30日**以内に **5,000**スターを超えている |
| **実利用の欠如** | 下記のいずれか（詳細は次項） |

| 該当した数 | 表示 |
|---|---|
| 0 | なし |
| 1 | 低 |
| 2 | 中 |
| 3以上 | 高 |

「低活動」と「実利用の欠如」は、fork 数や Issue 数という同じ事実を見ている部分があります。両方に当てはまった場合も、**1つとして数えます。**ひとつの状況を二重に数えると、疑いが実態より強く出てしまうためです。

### 「実利用の欠如」の判定

本来は GitHub の "Used by"（そのリポジトリを使っている他のリポジトリ数）を見たいのですが、**この数値は公式 API では提供されていません。**

そのため、代わりに次のシグナルを使い、**2つ以上**そろった場合に該当とします。

- リリースが1度も作られていない
- 作者以外の貢献者がいない
- スターが1,000以上あるのに Issue が1件もない
- スターが1,000以上あるのに fork がスターの1%未満

いずれも「スターは多いのに使われている形跡がない」を見るものなので、小規模なリポジトリは対象外です。

なお、"Used by" の数値をスクレイピングで取りに行くことはしません。公式に提供されていない経路に依存すると、壊れたときに気づけないためです。

### 確定した判定になるまで、しばらくかかります

「スター速度の異常」は過去7日ぶんの記録と比べるため、**検知したばかりのリポジトリは判定を確定できません。**

- 記録が7日ぶんたまるまでは、**それまでに観測できた増加の中央値**と比べる簡易な方法を使い、**「判定中」**と表示します
- 記録が1日もない場合は、判定そのものを行いません
- **「判定中」の結果は、疑いの段階（なし/低/中/高）には反映しません。**根拠としては表示しますが、確定していない材料で疑いを強めることはしません

なお Wakuru は、動きの少ないリポジトリを毎日は見に行きません（3日に1回、または週1回）。そのため、必要な7日ぶんの記録がたまるまでの期間は、暦の7日とは一致しません。**直近の記録が3日より古い場合は、急増の判定を行いません。**古い数字を根拠にした警告が残り続けるのを避けるためです。

## そのほかの警告

| 警告 | 条件 | 注意 |
|---|---|---|
| 数値に不自然さあり | fork がスターの **50%** を超える | 学習教材系のリポジトリでは正常に起きるため、その場合は **150%** まで許容します |
| 類似リポジトリ複数あり | 記号と末尾の数字を除いた名前が一致するものが、**14日**以内に別の作者から複数現れた | 同じ作者の関連リポジトリは対象外です。また `-go` `-rs` のような言語名は名前の一部として扱うため、正当な言語移植版どうしは対象になりません |

## ここは断定していません

**警告は「疑い」までしか言いません。**

判定はすべてヒューリスティック（経験則）です。研究論文自身が "suspected"（疑われる）という表現を使っており、誤検知があることを前提にしています。Wakuru の判定も同じです。

- 「偽スターです」とは言いません。「スター数の伸び方に不自然な点があります」と書きます
- 「このプロジェクトは危険です」とも言いません。品質の評価はしていません
- 警告がついていないことは、安全である証明にはなりません

**技術選定の最終判断は、必ず原典を確認してください。** Wakuru は、確認すべき点に気づくための道具です。

## 個別ページを作る基準

すべてのリポジトリに個別ページを作ることはしません。次のいずれかを満たしたものだけです。

- スター数が **1,000** 以上
- 1日のスター増加が **300** 以上
- 警告が1つ以上ついている
- 編集部が手動で「注目」に指定した

満たさないものは、一覧に行として載せるだけです。

**警告がついたページは必ず検索エンジンに載せます。** 判定結果が低いことを理由に隠すことはしません。低いこと自体が、読む方にとっての情報だからです。

なお、ページを作らないものは検索エンジンにも載りません（存在しないページなので当然です）。疑いがついていても、上の生成基準を満たさないものは一覧に載るだけになります。

## 誤りを見つけたら

判定に誤りがあると思われる場合は、お知らせください。閾値は運用しながら調整していく前提のもので、完成したものではありません。修正した場合は、この基準ページも合わせて更新します。
